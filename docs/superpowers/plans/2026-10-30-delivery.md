# Delivery (5a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A paid order turns into commands on the game server (RCON) without human action; the player sees the order state on the order page; the owner is emailed about stuck deliveries and can retry or mark them done in admin.

**Architecture:** The payment transaction writes `deliveries` (and `grants` for `TIMED`) rows; after commit a BullMQ job per delivery is added (`jobId = deliveryId`). A `worker` process (same image, other entrypoint) runs one delivery at a time through an `RconSender` seam and records the outcome in Postgres; a minutely sweeper recovers lost jobs and stuck `RUNNING` rows. Hourly expiry creates `REVOKE` deliveries; a 5-minute job emails the owners. Postgres is the source of truth; the queue is only a trigger.

**Tech Stack:** NestJS 11, Prisma 7, BullMQ (new, on the existing Redis), `rcon-client` (existing), Valibot, React Email via the existing `Mailer`, Next.js 16 + next-intl, RTK Query codegen, Jest + Testcontainers, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-30-delivery-design.md` (parent: `docs/superpowers/specs/2026-10-01-minecraft-donation-shop-design.md` §6.2, §8, §9.2–9.3)

## Global Constraints

- Business logic only in `apps/api`; the worker is the same image with another entrypoint. Next.js apps have no route handlers. Global prefix `/api`.
- Webhook rule (ADR 0010): dedupe by event id, conditional status updates, **side effects (queue, mail) after commit**; a queue or mail failure never fails payment handling.
- Commands only ever use the `{nick}` placeholder; a nick is rendered only if it matches `NICK_PATTERN` (`^[A-Za-z0-9_]{3,16}$`, `@shop/shared/orders`).
- Retry backoff after a connect failure: 10 s, 1 m, 5 m, 15 m, then 1 h; at most 10 attempts, then `FAILED`. A timeout or a connection lost after a command was written and before its reply → `NEEDS_REVIEW`, no automatic retry. Reply text is not inspected.
- `RCON_TIMEOUT_MS = 10_000` per connect and per command; a `RUNNING` delivery older than `STALE_RUNNING_MS = 300_000` is moved to `NEEDS_REVIEW` (`lastError = 'worker_lost'`).
- Worker concurrency 1. Schedulers: sweeper every minute, grant expiry every hour, owner alert every 5 minutes.
- The delivery's server is the order item's `serverId`; RCON host is re-resolved with `resolveRconHost` at send time (same SSRF guard as the admin test) and the connection goes to the returned IP.
- Order page: poll every 3 s, stop after 10 minutes, no polling for `none`/`delivered`. Player never sees errors or RCON data.
- `TIMED` clock starts when the `GRANT` delivery becomes `DONE`: `expiresAt = max(current expiresAt if not revoked, now) + durationDays × quantity days`, clearing `revokedAt`. One `grants` row per `(nick, serverId, productId)`.
- Admin routes: `@AdminController(path)` + `@RequirePermission(...)`, documented in `apps/api/src/openapi/` (`operationId`, `tags`, `summary`, `description`, response descriptions; `admin-routes.spec.ts` enforces). After contract changes: `pnpm --filter @shop/api openapi` then `pnpm --filter @shop/admin codegen`. New permission `delivery.resolve` (ADMIN and OWNER); add it the way `promo.write` was added (`git show d727bf7 --stat`, then follow it incl. role seeding).
- Texts: storefront `packages/messages/{en,pl}.json`, admin `apps/admin/messages/{en,pl}.json` (identical key sets, tests enforce), owner mail EN only in `apps/api/src/mailer/templates.tsx`.
- Money untouched. Do not bump ESLint (9) or TypeScript (6). New dependency only `bullmq` (reason in commit); check its job-scheduler API with Context7.
- TDD. Unit tests DB- and Redis-free; Postgres tests are `apps/api/test/*.int-spec.ts`.
- Gate before every commit: `pnpm format:check && pnpm lint && pnpm typecheck && pnpm test` (+ `pnpm --filter @shop/api test:int` for DB tasks).
- Conventional Commits; trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Run `graphify query "<question>"` before grepping; `graphify update .` after editing code.

## Review Focus

1. A nick that passes the form but is mangled, or a template that renders an injected command (`"x; op"`, spaces, newline) must never reach RCON — Task 3 test `renderCommands rejects a nick outside NICK_PATTERN`.
2. Redis down (or `enqueue` throwing) at payment time: the order is still `PAID`, the deliveries exist, and the sweeper delivers them later — Task 5 `queue failure does not fail the payment`, Task 7 `sweep enqueues due PENDING deliveries`.
3. A worker that dies mid-delivery must not cause a re-send: stale `RUNNING` goes to `NEEDS_REVIEW`, never back to `PENDING` — Task 7 `stale RUNNING becomes NEEDS_REVIEW`.
4. A product with no grant commands (or a `REVOKE` with none) completes immediately as `DONE` and the order becomes `DELIVERED` — Task 6 `empty command list is DONE`.
5. Buying a `TIMED` product again while active extends from the current expiry; buying after a revoke reopens the same row — Task 3 `grantExpiry` tests, Task 6 `repurchase extends`.

### Task 3: Pure delivery rules

**Files:**

- Create: `apps/api/src/delivery/delivery-rules.ts`, `apps/api/src/delivery/delivery-rules.spec.ts`

**Interfaces:**

- Produces:
  - `renderCommands(templates: readonly string[], nick: string, times: number): string[]` — replaces every `{nick}`, repeats the whole list `times` times in order; throws `Error('invalid_nick')` if `nick` fails `NICK_PATTERN`.
  - `MAX_ATTEMPTS = 10`, `retryDelayMs(attempt: number): number` — `attempt` is the number of failed attempts so far (1-based): 10_000, 60_000, 300_000, 900_000, then 3_600_000.
  - `type SendOutcome = {kind: 'done'; replies: string[]} | {kind: 'retryable'; replies: string[]; error: string} | {kind: 'unconfirmed'; replies: string[]; error: string}` (`replies` = replies to the commands that were sent in this call).
  - `type Next = {status: 'DONE'|'PENDING'|'FAILED'|'NEEDS_REVIEW'; attempts: number; nextAttemptAt: Date | null; lastError: string | null}` and `decideNext(attemptsBefore: number, outcome: SendOutcome, now: Date): Next` — `retryable` increments attempts and returns `PENDING` with `now + retryDelayMs(attempts)` until `MAX_ATTEMPTS`, then `FAILED`; `unconfirmed` → `NEEDS_REVIEW`; `done` → `DONE`.
  - `grantExpiry(current: {expiresAt: Date | null; revokedAt: Date | null}, now: Date, durationDays: number, quantity: number): Date`.
  - `publicDeliveryState(orderStatus: OrderStatus, statuses: readonly DeliveryStatus[]): PublicDeliveryState` — not `PAID`/`DELIVERED` or no deliveries → `'none'`; any `FAILED`/`NEEDS_REVIEW` → `'delayed'`; all `DONE` → `'delivered'`; else `'delivering'`.
